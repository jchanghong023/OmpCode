# OMP 核心命令对接工作流

需求权威：[omp-native-commands.md](../requirements/omp-native-commands.md)。本文件仅记录本次工程责任与门禁，不复制产品规则。

1. 编排者核对工作区基线、OMP 安装版本与协议；先更新需求。
2. 协议 Agent 核对安装核与对应源码，实施 omp-agent 目录、派发和输出投影的最小必要适配。
3. UI Agent 实施原生命令让位、完整参数传递及真实状态回投，复用既有界面。
4. 验证 Agent 补齐需求对应的自动化场景和隔离真实入口测试，提供证据与缺口；各 Agent 不提交、不合并、不宣称最终验收。
5. 编排者检查差异与状态所有权，执行 UT、真实 E2E、GUI、双链路、typecheck、lint、架构与格式门禁，记录实际结果并解决失败。
6. 全部相关验收通过后编排者提交并合入 `main`，保全主工作区无关改动，清理本次工作树。未完成验收不得标记完成或提前删除唯一工作成果。

唯一业务所有者为 OMP；使用现有目录、prompt、交互、投影与 admission 路径。Desktop 连续和 Web 可恢复交付共用派生事实；不新增 Host/UI 循环、goal 队列、索引或计划状态机。

原生命令历史验收只以 `command_output` 的稳定 ID、完整正文及逻辑顺序为事实。
虚拟列表的 `data-v4-turn-unit` / `data-index` 是扫描期间的逻辑槽位；动态测高、
历史折叠展开和 live tail 的流布局会改变像素坐标，坐标不能代替记录身份。
扫描器仍须拒绝同屏重复 ID、跨窗口同 ID 占据不同逻辑槽位、同槽位被不同 ID
替换、正文变化及挂载顺序倒置；冷恢复逐条严格比较完整 ID / 正文 / 顺序。
此修复仅更换 Desktop 验收扫描器的位置判据，不改变 OMP 事实所有权、
UI 分组、虚拟化、持久化或 live / recovery 交付边界；缺失逻辑槽位必须失败，
不得退化为文本去重或跳过断言。
