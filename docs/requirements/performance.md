# 性能热路径修复约束

## 产品规则与所有者

- 性能优化不得改变对话内容、任务状态、历史分页、订阅水位、桌面连续流与 Web 可恢复流的可见结果。
- UI workspace/task 状态由 `zcodeSessionStore` 持有；重复的相同状态通知不产生新引用。v4 投影由每个 `ConversationProjectionStore` 持有；收到一帧 deltas 后只发布一份完整、不可变的新快照，不修改此前发布的快照。
- omp 会话行与增量序列由 `ConversationProjection` 持有；流式文本可以内部缓冲，但 snapshot、rowsRange、终态 upsert 必须物化截至当前 seq 的完整文本。
- 编码预算由共享 wire codec 决定；分片必须保持物理帧上限、校验和、序号和原有错误语义。
- 代码高亮缓存属于 UI 内存缓存，可淘汰并重新计算，不是历史数据权威源。
- UI 仅订阅渲染或事件回调实际需要的 workspace 字段；workflow 联接表只因其来源行变化失效。设置页等非首屏组件可异步装载，打开时必须可用。
- 对话查找输入立刻回显；昂贵的全文匹配与历史回源在输入稳定 150ms 后执行。切换范围、关闭及清空查询必须取消或覆盖待处理的旧查询。
- 桌面“打开方式”的编辑器探测不能在主线程同步等待外部命令；已知静态安装路径优先，命令兜底异步执行，同一次探测结果复用。
- Agent stdio 适配器按会话串行处理有状态命令；一个会话的慢历史读取不得阻塞其他会话的命令、停止请求或实时帧。同一订阅的 ACK 必须先于该请求产生的首帧，独立会话的帧无需等待此 ACK。请求处理期间定时器产生的后续帧不得延迟到请求结束：同一 topic 的帧必须按生成顺序上线，否则客户端按断档进入恢复。
- 冷会话目录读取应有界并按 ID 直接定位；标题只读取需要的文件头部，长会话恢复避免一次性拆分整个文件产生额外内存峰值。时间线的运行计时和单轮流式变化不得重新计算未变化的全部历史轮次。
- `@` 文件引用的本地补扫与元数据访问按 workspace 复用：同一索引版本内不重复扫描同一目录，同 workspace 在途扫描只合并等待而不另起并发扫描，ignore 规则解析结果缓存至规则文件变化；规则修改或新增文件在下一次补扫仍能被发现。
- 文件索引与 ignore 规则缓存由 Host 的 file service 实例唯一持有，按 `workspaceIdentity?.trim() || workspacePath` 隔离，同时校验实际 rootPath。不同无命中前缀复用同一轮补扫；显式刷新及规则变化仍能发起新一轮扫描，旧扫描的延迟结果不得覆盖新索引，缓存和刷新记录均有容量边界。
- ignore 规则读取失败时的降级 matcher 仅用于当前请求，不绑定到成功 stat 的文件指纹长期缓存；后续刷新或重扫重新读取规则，读取恢复后排除规则立即恢复。缓存命中不得使降级规则永久保留。
- 文件 mention 的新轮次由实际输入中的清空/重新打开动作决定，在接纳动作时同步更新，不能等待旧 RPC 完成或依赖 deferred query 必然经过空串。过时响应仍不得展示或消费新轮次的补扫名额。
- 时间线渲染缓存只持有派生视图：计时更新复用既有分组，只更新运行轮；单轮文本增量不重新物化未变化轮次。历史追加、替换、移除、分页前插及运行状态变化仍按投影顺序生成完整视图，不通过截短历史减少开销。
- 工具行查找索引由 `ConversationProjection` 与 rows 一起维护；工具更新按 toolCallId 定位，水合、行替换、删除及恢复时索引与行一致，不另设工具事实所有者。
- 折叠思考仍显示最新有效摘要，避免为摘要生成累计全文的多份副本；展开后显示完整原文。流式代码更新保持同一代码块的组件身份，内容变化不以全文哈希驱动重挂载；代码复制、主题、语言与完成态高亮仍消费完整最新内容。
- 传输饱和时每个连接的未发送字节必须有上限；桌面连续流不得静默丢帧，Web 恢复流可按同一会话水位补发或重取快照。流控状态由订阅发布器接收，重连和取消订阅清理连接状态。
- 协议帧只编码一次；调试日志关闭时不得为日志额外编码帧。桌面主进程的生产日志异步写入，退出前刷盘，错误日志保持可见。

## 状态与时序

```text
omp 事件 → ConversationProjection（seq、rows、pending）→ topic frame
  → desktop-continuous 直接递交 / web-remote-replayable 快照+缺口修复
  → ConversationProjectionStore（一帧一候选快照）→ UI selector/时间线
```

重复通知不增加 UI 状态版本；新帧按原序应用，旧快照可供并发 reader 使用。断线仍按既有恢复路径处理。

```text
同轮 @ 查询 → fileService 索引 owner → 复用在途检查/扫描 → 当前代际索引
规则保存 / rootPath 改变 → 失效代际 → 等旧扫描结束 → 新扫描 → 校验代际后写缓存
工具事件 → ConversationProjection rows + 工具 ID 索引 → 原 seq/delta 交付
不可变历史行 → 时间线内容缓存 → 导航/查找
运行计时 → 同一派生缓存中的运行轮时长 → 展示（不重建内容索引）
```

## 验收场景

1. 重复的 streaming 状态不触发 workspace store 订阅者；状态、错误或 provider 变化仍通知。
2. 同一帧多条 row.delta 的结果与逐条不可变应用一致，原快照保持不变；追加、更新、移除和状态 patch 均一致。
3. 长文本多 chunk 后，在线 delta、运行中 snapshot、rowsRange 与完成态文本一致。
4. 分片临界帧不越限，重组结果与原逻辑帧一致；无须分片的帧保持原格式。
5. 缓存达到容量后淘汰旧条目，重新访问可再次生成相同结果。
6. 桌面 GUI 用现有 omp 配置中的 `zhipu-coding-plan/glm-5.3-flash` 完成新建会话、发送消息、查看流式及完成态，并检查基本导航。
7. 打开设置页与返回工作区不丢失当前会话；打开终端仍可显示面板。
8. GUI 打开查找框连续输入关键词，只以最终关键词显示命中和高亮；关闭后高亮清除，重新打开不沿用旧搜索。
9. GUI 打开“选择打开方式”后能列出可用编辑器，命令探测不阻塞主窗口其它交互。
10. 人为挂起会话 A 的历史读取，会话 B 的实时帧与停止命令仍能完成；A 的订阅仍按 ACK → 首帧顺序交付。
11. 使用相同的大目录和长会话样本比较优化前后的列表、恢复、时间线流式更新耗时和内存峰值，并把草稿持久化写入次数、目录扫描次数与历史遍历轮次计入同一测量；结果与历史分页一致。
12. 慢 WebSocket 与饱和 MessagePort 下缓冲保持有界；恢复后同一 seq 的桌面连续交付与 Web 快照/缺口修复均不丢最终结果。
13. 关闭调试日志后每帧只有一次协议编码；大量日志期间主窗口不被同步文件 I/O 阻塞，退出时日志完整。
14. 工作区上下文尚未就绪时打开引导/设置，再将 workspace 从缺省切到真实路径、远端 identity 并清空：同一已挂载组件的 Hook 调用顺序保持稳定；缺省目标使用当前上下文服务，明确目标仍按既有 workspace/identity 隔离路由，不触发 React Hook 顺序异常或引导错误边界。
15. 对同一 workspace 连续输入多个不同的无命中文件前缀，普通查询和刷新查询共用在途扫描，扫描数不随字符数增长；创建新文件后下一轮补扫或显式刷新能检出。编辑 ignore 规则后结果生效；旧请求完成、重连及同路径不同 identity 不污染当前索引。
16. 以相同的长历史样本分别执行仅计时更新、当前轮流式文本更新及历史分页：验证未变化轮次引用复用、分组/行访问计数减少，最终可见轮次、顺序及全文一致。
17. 通过真实投影入口更新已存在和新增工具，覆盖历史水合、工具行替换/移除及工具完成；查找不复制/遍历全部历史，工具状态、结果和文件统计仍一致。
18. GUI 在长思考和代码回答中检查折叠摘要、展开原文、复制全文、主题切换及完成态；连续流式代码更新不重挂载同一代码块，旧内容不残留。Desktop continuous 与 Web replayable 的同一最终内容均正确。
19. `.zcodeignore` 指纹可读、正文读取暂时失败时，当前请求可降级；恢复读取后普通查询/显式刷新或 TTL 重扫重新应用排除规则。覆盖 fallback-gitignore 与 fallback-builtin，不把降级 matcher 或索引当作有效规则版本长期保存。
20. 首次无命中补扫后创建新文件，保留 `@` 清空并在空查询 RPC 返回前重新输入，仍开启新轮次并找到文件；旧空查询失活及 deferred query 跳过空串均不吞掉该轮补扫。
21. 真实 GUI 的流式代码验收比较完整预期代码行及顺序，冷恢复比较同一完整结果；主题/高亮验收在产品 worker provider 下检查实际 token 和主题颜色，不能仅以修改 props、首尾文字或容器身份作为通过依据。

## 边界

本域不更改 omp 用户配置或协议能力位；全局边界见 [FORK.md](FORK.md)。强制更新门禁不在本域内。背压、日志和历史完整性依照本页验收，不以静态检查代替运行测量。

性能改动须有改动前后同一场景的测量，重点包括大模型目录渲染和冷会话扫描，不为无证据的瓶颈增加状态或缓存。
